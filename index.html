Core Engine Systems

Quick diagrams for enemy AI, hearing/vision, and the mission loop. Deeper demos are in Tech Demos.

Enemy AI state machine

Purpose: Enemy starts asleep, then investigates noise, chases if he sees you, or searches if you hide.

  • Dormant: enemy waits until something wakes him up
  • Investigate: a footstep or wall bump was heard nearby
  • Chase: enemy can see Suneku in his vision cone
  • Search: you escaped sight, then he checks the area and calms down

Stealth Perception Stack

Purpose

  • Green wedge shows where Enemy is looking. Step in and he may chase.
  • Yellow ring is Enemy’s hearing radius. Noise inside it triggers investigate.
  • Red pulse is noise from Suneku (footsteps, sprinting, hitting a wall)

Build & run on macOS

Requirements: macOS 12+, Xcode Command Line Tools, Homebrew. Install dependencies once:

brew install cmake sdl2 sdl2_image glew pkg-config

Clone and build

git clone https://github.com/AMGKompressor/Boxu.git
cd Boxu/source
cmake -S . -B ../temp/build-boxu -DCMAKE_BUILD_TYPE=Release
cmake --build ../temp/build-boxu --config Release

Run: launch from the game folder so textures, sounds, and shaders resolve:

cd ../game
../temp/build-boxu/gpframework

Tip: if CMake cannot find SDL2, add Homebrew to your PATH (brew --prefix).

Enemy AI State Machine

Purpose

Employers can see structured enemy AI beyond simple chase behaviour.

Challenge

Balancing wake-on-noise, vision cone detection, and search cooldown without pathfinding.

Approach

OcelotState FSM: Dormant → Investigate → Chase → Search with hearing radius and vision cone checks.

Result

Enemy responds to wall hits and line-of-sight; debug hearing overlay visualises awareness.

Reflection

Add grid or nav-mesh pathfinding so Enemy respects walls during chase.

enum class OcelotState {
  Dormant, Investigate, Chase, Search
};

Collision & OBB

Purpose

Shows physics-adjacent programming and debugging discipline.

Challenge

Red wire outline did not match player stop distance; AABB was too fat vs rotated sprite.

Approach

True OBB support along wall normals; per-edge contact; same basis as renderer draw path.

Result

Sliding along walls feels correct; H toggles hitbox debug overlay.

Reflection

Prototype collision in isolation before merging with gameplay code.

Vision & Shaders

Purpose

Demonstrates graphical effects and shader pipeline usage.

Challenge

Early vision wedge was partially blind; tied to player position not only facing.

Approach

GLSL vision_mask fragment/vertex shaders dim world outside mouse-aim cone.

Result

Stealth readability improved; debug mode disables overlay for level editing.

Reflection

Unit-test shader uniforms separately from gameplay facing logic.

Stealth Audio

Purpose

Audio as a gameplay mechanic: noise radius alerts enemies.

Challenge

Wall thud spammed every frame; SDL_LoadWAV does not load MP3.

Approach

Edge-triggered wall hits; PCM thud.wav; randomised footstep clips; separate walk and sprint noise radius.

Result

Walk/sprint produce different noise pulses visible when H is enabled.

Reflection

Confirm SDL-only SFX policy with lecturer; consider FMOD if required for Gold.

Vision Wedge Shader

Purpose: In Boxu, the level is mostly hidden in darkness. A cone of light follows your mouse. That is what Suneku can “see.” This demo recreates that effect in the browser.

  • Lit floor is the area you are currently looking at
  • Dark fog covers everywhere else on the map
  • Red walls block sight. The wedge stops at the wall, not through it.
  • Yellow hint: try peeking around the corner down-left. Text only appears when you look at it.

Challenge: Early versions cut off the whole cone when any ray hit a wall.

Approach: A custom shader checks each direction separately so only the blocked slice stays dark.

Result: Stealth reads clearly. You feel blind until you aim, and corners matter.

OBB Collision Debug

Purpose: Show how Boxu knows when Suneku touches a wall. The red outline is the collision box. It must match what you see on screen.

  • Red outline is the rotated hitbox (OBB), not a simple square
  • Wall slide keeps the character flush with the wall instead of sticking or clipping

Challenge: A plain square hitbox was too wide and the debug outline did not match stop distance.

Approach: Oriented bounding boxes aligned to the sprite and each wall edge.

Result: Movement feels fair; press H in-game to toggle this debug view.

Noise Pulse Rings

Purpose: Sound is a gameplay mechanic. Enemy hearing matches Suneku’s noise: a 140 px walk radius and a 320 px sprint radius. Noise inside either ring can trigger investigate.

  • Walk (blue pulse) is quiet, with a smaller ripple (~140 px in-game)
  • Sprint (red pulse) is loud, with a larger ripple (~320 px)
  • Yellow ring flashes with sprint noise (320 px)
  • Inner blue ring flashes with walk noise (140 px)

Challenge: Wall bumps fired every frame and were too noisy.

Approach: Separate walk and sprint noise radius, and only play a thud when contact first starts.

Result: Players learn to walk quietly near the Enemy and sprint only when safe. Press H to see rings in-game.

Group Game Project

COMP710 group game. It runs on cardBoardEngine, the C++ engine I split out from Boxu for Mac and Windows builds.

cardBoardEngine

Standalone C++ repo, not part of Boxu. Clone AMGKompressor/cardBoardEngine only, then add the lib/ folder with SDL2, SDL2_image, and GLEW as described in the repo README.

View cardBoardEngine on GitHub

Purpose

Turn Boxu’s working code into a modular engine the group game could grow on.

Challenge

One huge game.cpp was hard to share, and we needed reliable Mac and Windows builds.

Approach

Split code into framework/, Player/, Map/, and a small app loop. Two builds: cardboard (demo) and tgp (full game).

Result

Reusable movement, collision, vision, and audio modules, plus enemies, batteries, and map tuning in tgp.

betaVersionV2-windows

Latest branch adds:

  • Pathfinding: grid + BFS so enemies go around walls (debug with H)
  • Minimap: corner map with nearby enemy dots
  • Polish: flashlight stun, batteries, ImGui tuning

Flashlight

Built on Boxu’s shaders:

  • Small lit bubble around the player
  • LMB flashlight with limited charge
  • Batteries refill charge
  • Space stun cone on enemies

Controls (tgp / betaVersionV2-windows)

WASD move · Shift sprint · LMB flashlight · Space stun beam · H debug (hitbox, footstep rings, BFS walkable nodes) · ` ImGui (minimap radius, batteries) · Esc quit

Build & run (macOS & Windows)

macOS (from repo root; Homebrew once: cmake sdl2 sdl2_image glew)

cmake -B build
cmake --build build
./build/tgp

Windows: Visual Studio 2022 (Desktop C++), CMake, lib/ in place, Win32:

cmake -G "Visual Studio 17 2022" -A Win32 -B build
cmake --build build --config Release
cd build\Release
tgp.exe

Modular-only demo: cardboard.exe (set CARDBOARD_BUILD_FULL_GAME=OFF at configure time).

Place SDL2.dll, SDL2_image.dll, and glew32.dll next to the executable (from lib/). For minimap + BFS pathfinding, clone and check out betaVersionV2-windows before building.
